## 1. BUY 진입 게이트 전수 (코드 실제 순서)

진입은 아래를 **전부** 통과해야 함. 하나라도 FAIL이면 `OrderSend` 없음.

| 게이트 | 조건 | 스샷A | 스샷B | 판정 |
|--------|------|-------|-------|------|
| G1 | Cycle == BUY | BUY | BUY | PASS |
| G2 | CrossBar ≤ 55 | 29/55 | (동일 사이클 추정) | PASS |
| G3 | Traded == NO | NO | NO | PASS |
| G4 | 순수 50EMA 터치 무장 + Grace 1..3 | **NO_TOUCH / Grace OFF** | **NO_TOUCH / Grace OFF** | **FAIL ← 1차 차단** |
| G5 | (Grace 안에서만) 9EMA High&Close 위 | WAIT_TOUCH = **미평가** | WAIT_TOUCH = **미평가** | 평가 안 함 |
| G6 | (Grace 안) 양봉 품질 | WAIT_TOUCH = **미평가** | 미평가 | 평가 안 함 |
| G7 | RSI ≥ 52.5 | 값 62.02 (참고) | 값 40.79 (참고) | Grace 없어 미적용 |
| G8 | Dist ≥ **100** | 값 327.0 | 값 90.0 | Grace 없어 미적용 |
| G9 | Angle ≥ **15.0** | 값 14.07 | 값 -2.15 | Grace 없어 미적용 |

**코드 사실:** `Grace OFF` 이면 FastEMA/Candle는 의도적으로 `WAIT_TOUCH`만 찍고, `CheckEntrySetupBuy()`를 **호출하지 않음**.

## 5. 50EMA 터치 재검수 (최중요)

### 5-1. EA/명세 순수 터치 정의 (바늘 관통 포함)

```text
BUY: Open > EMA50 AND Close > EMA50 AND Low <= EMA50
```

- `Low <= EMA50` → 꼬리가 선을 **스치거나 찔렀다 빼는(관통) 터치 포함**
- 수평선에 “정확히 한 점만” 요구하지 않음
- **금지:** Open 또는 Close가 EMA50 **미만** (= 몸통 침범 = 돌파)

### 5-2. 스샷이 찍은 EA 판정

| 증거 | 해석 |
|------|------|
| `Last: ANTI_BREAKOUT_BUY` (스샷A) | 이 BUY 사이클에서 몸통 하향 침범으로 터치/유예 리셋 발생 |
| `AntiBreak: RESET_BELOW_50` (스샷B) | **시가 또는 종가 < EMA50** 로 판정된 봉 |
| `50EMA Touch: NO_TOUCH` + `Grace: OFF` | 순수 터치 래치 미무장 → 진입 셋업 미가동 |

### 5-3. “파란선=50EMA에 꼬리가 닿아 보이는데?”에 대한 검수 결론

- 파란선 = 50EMA 라는 전제: **사용자 확인 그대로 수용**
- 화살표 봉이 눈으로 50EMA에 닿아 보이는 것: **시각적으로 접촉 모양으로 보임 (부정하지 않음)**
- 그러나 EA 진입용 “순수 터치 무장”은 스샷상 **성립하지 않음**
- 이유(스샷 문자 증거):
  1. `RESET_BELOW_50` / `ANTI_BREAKOUT_BUY` = **몸통(시가/종가) 침범**으로 분류됨  
     → 명세상 터치 불허 (돌파 절대 불허)
  2. 또는 터치가 한때 성립했어도 안티브레이크로 **Grace가 죽은 뒤** 스샷이 찍힘  
     (`Grace: OFF`, `Traded: NO`)
  3. 스샷B 시각(18:39)은 화살표 봉(~17:44)과 **동일 봉 스냅샷이 아닐 수 있음**  
     → 대시보드는 “마지막 확정봉” 상태

### 5-4. 허위 보고 금지 항목

- “이격/각도만 문제였다”고 단정하는 것 → **부정확** (1차 차단은 Grace OFF)
- “50EMA 접촉 자체를 부정”하는 것 → **부정확** (시각 접촉과 EA 순수터치 래치는 별개)
- “파라미터를 안 보고 말했다” → 본 재검수에서 **이격 100 / 각도 15 전수 대조 완료**

## 6. 미진입 원인 — 최종 인과사슬 (장난 없이)

### 1차 확정 원인 (스샷A·B 공통)
**`Grace: OFF` / `50EMA Touch: NO_TOUCH`**  
→ 진입 필터 함수 미호출 (`WAIT_TOUCH`)  
→ `ENTRY READY: NO`  
→ BUY 주문 없음

### 1차를 만든 상태머신 사건 (스샷 문자)
**`Last: ANTI_BREAKOUT_BUY` / `AntiBreak: RESET_BELOW_50`**  
→ Open 또는 Close가 50EMA 아래로 판정 → 터치/유예 리셋

### 2차 (만약 Grace가 켜져 있었다면) — 스샷A 숫자로 확정
| 필터 | 값 | 기준 | 결과 |
|------|-----|------|------|
| 이격 | 327.0 | ≥100 | PASS |
| 각도 | **14.07** | **≥15.0** | **FAIL** |
| RSI | 62.02 | ≥52.5 | PASS |

→ Grace가 살아 있어도 스샷A 시점에는 **각도 15.0 미달로 진입 불가**.

### 2차 보강 — 스샷B 숫자
이격 90<100, 각도 -2.15<15, RSI 40.79<52.5 → 전부 FAIL.

## 7. 코드 재검수 (해당 구간 버그 여부)

| 검사 | 결과 |
|------|------|
| 바늘 터치(`low<=EMA50`, 몸통 위) 포함 여부 | **포함됨** (수식 존재) |
| 몸통 침범 시 터치 금지 | **동작함** (AntiBreak) |
| Grace OFF 시 필터 미평가 | **의도된 동작** (`WAIT_TOUCH`) |
| 이격 비교 `>= InpMinEmaDistancePts` | **정상** |
| 각도 비교 `>= InpMinEmaAngle` | **정상** |
| 대시보드 Dist/Angle이 Grace OFF여도 숫자 표시 | **정상** (참고값). OK/FAIL 접미사는 Grace 안에서만 붙음 |

**이번 스샷만으로 “시각 접촉인데 low<=EMA50 수치 실패”인지 “몸통 침범”인지는 OHLC 원숫자가 없어 100% 한쪽만 단정 불가.**  
다만 스샷B의 `RESET_BELOW_50`는 **몸통 침범 판정**을 EA가 내린 직접 증거임.

## 8. 최종 판정 문장

1. **BUY 미진입 1차 원인:** 순수 50EMA 터치 래치 미무장(`NO_TOUCH`) → `Grace OFF` → 셋업 미평가.  
2. **그 상태의 직접 표시:** `ANTI_BREAKOUT_BUY` / `RESET_BELOW_50` (몸통 하향 침범).  
3. **이격도(100):** 스샷A에서는 통과 가능(327). 미진입의 1차 원인 아님.  
4. **각도(15.0):** 스샷A에서 14.07로 **미달**. Grace가 있어도 막히는 2차 원인.  
5. **RSI:** 스샷A에서는 통과 가능. 1차 원인 아님.
