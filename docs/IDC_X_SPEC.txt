1. 시스템 기본 환경 (System Environment)
-------------------------------------------------------------------------------
- 시스템 정체성: GOLD M1 타임프레임에서 EMA 크로스로 큰 추세를 규정하고, 
  50EMA와의 정밀 상태머신(State Machine) 비교 연산을 통해 오진입을 완벽히 차단하며 
  추격을 집행하는 고도화된 추세 추종 시스템.
- 대상 상품: Gold (XAUUSD 및 브로커별 GOLD 관련 모든 계열 심볼)
- 타임프레임: M1 (1분봉)
- 연산 작동 원칙: 실시간 틱 데이터 간섭 및 시차 오차를 원천 배제하기 위해, 
  모든 캔들 판단, 가격 비교, 지표 계산은 완전히 마감되어 데이터가 확정된 
  "1번 완성봉(bar 1)" 데이터만을 기준으로 물리적 순차 제어 가동함.
- 청산 기본 원칙: 이익실현(TP) 라인은 일절 사용하지 않으며, 오직 고정 손절선(SL)과 
  진입가 기준 고정 포인트 추격형 트레일링 스탑으로만 수익을 확보하고 탈출함.

-------------------------------------------------------------------------------
2. 시스템 파라미터 규격 (System Parameters)
-------------------------------------------------------------------------------
- InpShowDashboard     (bool)   : 화면 실시간 모니터링 대시보드 출력 스위치 (true/false)
- InpDashboardFontSize (int)    : 대시보드 글자 크기 (기본값 12)
- InpAutoDetectGold    (bool)   : 브로커별 골드 심볼 접미사 포함 자동 스캔 활성화 (true)
- InpManualSymbol      (string) : 수동 심볼 강제 지정 (비워둘 시 자동 스캔 연동)
- InpFastEmaPeriod     (int)    : Fast EMA 기간 (기본값 9)
- InpSlowEmaPeriod     (int)    : Slow EMA 기간 (기본값 50)
- InpTrendEmaPeriod    = 34     : 시각 각도 연산용 기본 트렌드 EMA 기간 (기본값 34)
- InpRsiPeriod         = 14     : RSI 기간 (기본값 14)
- InpRsiUpper          = 52.0   : RSI 상단 기준선 (기본값 52.0)
- InpRsiLower          = 48.0   : RSI 하단 기준선 (기본값 48.0)
- InpObservationBars   (int)    : 크로스 발생 직후 최대 대기 관찰 봉 수 (N봉, 기본값 55)
- InpEmaGraceBars      (int)    : 50EMA 순수 터치 후 진입 유예 봉 수 (N봉, 기본값 3)
- InpMinEmaDistancePts (int)    : 횡보장 차단용 최소 9-50EMA 이격 거리 포인트 (기본값 30)
- InpMinEmaAngle       (double) : 추세장 유효성 판정용 최소 34EMA 시각 각도 (기본값 5.0)
- InpLots              (double) : 주문 진입 랏 사이즈 (기본값 0.50)
- InpStopLossPoints    (int)    : 진입 즉시 강제 주입되는 필수 안전 손절 포인트 (기본값 200)
- InpTrailingStartPts  (int)    : 진입가 기준 1차 SL 본전 이동 수익 포인트 (기본값 200)
- InpTrailingStepPts   (int)    : 1차 확보 이후 추격할 계단식 Floor 래치 스텝 포인트 (기본값 10)
- InpMagicNumber       (int)    : 시스템 고유 매직넘버 (기본값 80008)
- InpSlippagePts       (int)    : 최대 허용 슬리피지 포인트 (기본값 30)
- InpTradeComment      (string) : 주문 인식용 코멘트 (기본값 "IDC_X")

3. 이중 N봉 및 상태머신 제어 메커니즘 (State Machine & Logic Control)
-------------------------------------------------------------------------------
[3-1] 크로스 판단 및 전체 리셋 (Cycle Initialization)
- 1분 완성봉 기준으로 9EMA가 50EMA를 상향 돌파하면 BUY 사이클(+1), 하향 돌파하면 SELL 사이클(-1) 개시.
- 크로스가 새로 일어나는 시점에 전체 경과 봉수 카운터(`g_CrossBarIndex = 1`), 
유예 플래그 및 카운터(`g_50EmaTouched = false`, `g_GraceBarCounter = -1`), 
진입 소진 여부(`g_IsTradedInCycle = false`)를 완전히 청소 및 초기화함.

[3-2] 관찰 윈도우 제약 (Observation Window Filter)
- 새 봉 생성과 동시에 `g_CrossBarIndex`는 1씩 자동 누적 증가함.
- `g_CrossBarIndex > InpObservationBars` (설정값 초과) 시 해당 사이클은 논리적으로 즉시 사망 처리되며, 
   모든 진입 제어 신호와 유예 플래그는 메모리 상에서 완벽히 소멸(`false`, `-1`) 처리됨.
- 하나의 크로스 사이클 내에서 신호 발생 및 주문 체결은 오직 '단 1회'로 제한되며, 
  체결 성공 여부와 무관하게 신호는 즉시 소진됨.

[3-3] 유예 기간 및 좀비 카운터 부활 방지 래치 (Grace Period & Latch Lock)
- 새 봉 생성 시 유예 상태가 가동 중이라면 `g_GraceBarCounter` 역시 1씩 누적 증가함.
- 만약 `g_GraceBarCounter > InpEmaGraceBars` (설정 유예 기간 초과) 조건이 달성되는 바로 그 봉의 시작 시점에는, 
  당해 봉 하단의 실시간 틱 데이터나 캔들 데이터가 카운터를 기습적으로 부활시키지 못하도록 
  `g_50EmaTouched = false`, `g_GraceBarCounter = -1` 처리와 함께 당해 봉 판단을 건너뛰게 만드는 
  강제 격리 래치 락(Latch Lock) 필터를 주입함.

4. BUY 진입 조건 및 셋업 명세 (BUY Trade Rules — SELL은 대칭 적용)
-------------------------------------------------------------------------------
골든크로스 사이클(`g_CycleDirection == 1`) 내부에서 관찰 윈도우 한계 봉 수 이내에 
다음 순서대로 제어가 발동되어야 한다.

[4-1] 장대봉 관통 이탈 시 즉각 소멸 규칙 (Anti-Breakout Reset)
- 1번 완성봉의 종가(`Close`) 또는 시가(`Open`) 중 어느 하나라도 50EMA 미만으로 완전히 하향 침범하여 
마감한 캔들이 출현하면, 장대 관통 변동성 확대로 간주하여 기존에 기억하고 연명하던 모든 
유예 상태(`g_50EmaTouched = false`, `g_GraceBarCounter = -1`)를 실시간 즉시 강제 소멸시킴.

[4-2] 순수 터치 조건 충족 (Pure 50EMA Touch Definition)
- 돌파 마감 이탈봉이 아니라는 전제하에, 1번 완성봉의 몸통(시가와 종가)은 완벽히 50EMA 위에 
  안정적으로 안착해 있으면서, 오직 저가(`Low`, 하단 꼬리)만 50EMA 이하로 스치거나 찌르는 구조를 만족해야 함.
- 산술 수식: `if(open1 > slowEmaLive && close1 > slowEmaLive && low1 <= slowEmaLive)`
- 위 조건이 충족되는 순간에만 정석 터치로 판정해 유예 플래그를 고정하고 유예 카운트를 
  1봉으로 즉시 기동함 (`g_50EmaTouched = true; g_GraceBarCounter = 1;`).

[4-3] 최종 진입 셋업 캔들 조건 정렬
유예 기간 내부(`g_GraceBarCounter`가 1 이상이자 설정값 이하) 범위 내에서 매 마감 봉마다 다음 4가지 조건을 동시 체크함.
1) 9EMA 상향 돌파 이탈: 완성봉의 고가(`High`)와 종가(`Close`)가 모두 빠른 선(9EMA) 위에 완벽히 마감되어야 함.
2) 양봉 캔들 품질 수식: 반드시 순수 양봉이어야 하며, 위꼬리/아래꼬리의 변동성 왜곡을 이겨낸 견고한 몸통 캔들이어야 함.
   - 격리 산술식: `(close1 > open1) && ((close1 - open1) > ((high1 - close1) + (open1 - low1)))`
3) RSI 최종 확인 필터: 미세 오차 및 데이터 왜곡을 방지하기 위해 버퍼를 가산하여 안착 여부를 판단함.
   - 판정식: `rsi1 >= (InpRsiUpper + 0.5)`  (52.0 + 0.5 = 52.5 이상 명확히 안착 필 필수)
4) 고급 연산 필터 (이격도 및 34EMA 시각 각도):
   - 이격도: 1번 완성봉 기준 9-50EMA 간의 거리가 사용자 설정 포인트(`InpMinEmaDistancePts`) 이상 확보되어야 횡보장 진입이 차단됨.
   - 시각 각도: 차트의 픽셀 해상도(X축 봉 개수/Y축 픽셀 피치) 변화율을 arctan 수식에 대입해 연산한 
     34EMA의 실시간 각도가 `InpMinEmaAngle` 이상 분출 중이어야 함.

[4-4] 진입 집행 (Execution)
- 위 모든 조건이 유예 범위 안에서 동시에 완벽 정렬되어 마감되는 동시(다음 봉 첫 틱 시작점)에 BUY 포지션을 
  시장가로 즉시 집행하며, 해당 사이클 신호는 영구 소진됨.

-------------------------------------------------------------------------------
5. 수익 확보형 고정 포인트 트레일링 스탑 메커니즘 (Trailing Stop Rules)
-------------------------------------------------------------------------------
- 실시간 가격 변동 호가에 SL이 역산되어 뒤로 밀리거나 오차가 누적되는 결함을 완전 차단하기 위해, 
 실시간 현재가가 아닌 오직 최초 포지션 진입가격(`OrderOpenPrice()`)만을 고정 절대 기준점으로 격리 연산함.

[5-1] 1차 트리거: 시작점 강제 이동 (Base Line Lock)
- 진입가 대비 실시간 호가 수익이 사용자 설정 포인트(`InpTrailingStartPts`, 기본 200pt)에 정확히 도달하는 순간, 
  손절 라인을 진입가 방향으로 순간 이동시켜 본전선 익절 마진을 최초 강제 확보함.
  - BUY 포지션 1차 이동 SL 목표가 = `OrderOpenPrice() + (InpTrailingStartPts * Point)`
  - SELL 포지션 1차 이동 SL 목표가 = `OrderOpenPrice() - (InpTrailingStartPts * Point)`

[5-2] 2차 추격: 계단식 스텝 버림 연산 (Floor Math Step)
- 1차 베이스 라인이 안착된 이후 수익이 추가로 연이어 분출될 때, 설정 스텝(`InpTrailingStepPts`, 기본 10pt) 단위로 수학적 버림 연산(`MathFloor`)을 
적용하여 정확히 설정 간격이 꽉 채워질 때만 계단식으로 손절선을 전진 추격함.
  - BUY 계단 연산식 : `int steps = (int)MathFloor((현재수익포인트 - InpTrailingStartPts) / InpTrailingStepPts);`
  - BUY 최종 이동 SL = `OrderOpenPrice() + (InpTrailingStartPts * Point) + (steps * InpTrailingStepPts * Point);`
- 오직 트레이더에게 유리한 방향(기존 SL보다 상단/하단)으로만 전진 수정을 허용하며, 불리한 수정이나 
  에러 발생 시 기존의 유효한 손절 라인을 무결하게 유지함. 브로커의 `STOPLEVEL` 마진 연산 필터를 상시 가동해 수정 거부를 완벽히 우회함.
